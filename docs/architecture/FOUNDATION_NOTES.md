# Foundation implementation notes

What the development foundation implements, where it follows the design exactly, and every place where implementation needed a decision the design did not make. Nothing here changes the SRS. Items marked **proposed** need the team's or the mentor's agreement before they are recorded in D11.

| Area | Implemented | Design reference |
|---|---|---|

| Settings | Environment-based (`pydantic-settings`), secrets as `SecretStr`, production guards | D10 §2 (SEC-18) |

## 2. Implementation decisions

| ID | Decision | Reason | Status |
|---|---|---|---|
| IMP-01 | PostgreSQL runs in **WSL2 Ubuntu from the official PGDG apt repository**, not natively on Windows or in Docker | pgvector has no Windows binaries (a native build needs Visual Studio Build Tools). Docker Desktop is not installed and costs RAM. PGDG ships exactly 18.7 and pgvector 0.8.7. Needs no admin rights. See `docs/setup/WINDOWS_SETUP.md` §4 | Decided for development. EXP-10 still measures performance |
| IMP-02 | Three database URLs (`DATABASE_URL` for app_api, `DATABASE_WORKER_URL` for app_worker, `DATABASE_MIGRATION_URL` for app_owner) and a separate `elucis_test` database | D07 §5 defines the three roles; RLS only applies to non-owners. Tests must never touch dev data | Follows design |
| IMP-03 | **TypeScript 6.0.3**, not 7.x | TypeScript 7 (native port) is newer, but `typescript-eslint` 8.x supports TypeScript `>=4.8.4 <6.1.0`, so type-aware linting would not work | Revisit when typescript-eslint supports 7 |
| IMP-04 | `httpx2` instead of `httpx` | Starlette 1.10 (inside FastAPI) deprecates `httpx` for its test client in favour of `httpx2`, the maintained successor; using one HTTP library everywhere avoids two stacks | Decided |
| IMP-05 | Node.js `>=22.22.0`, using the latest Node.js 22 LTS (winget `OpenJS.NodeJS.22`). Not `OpenJS.NodeJS.LTS`, which now installs Node 26, a version this project has not been verified on | React Router 8 requires Node 22.22+; Vite 8 requires 20.19+ or 22.12+ | **Closed** 26 Nov 2026: laptop upgraded from 22.20.0 to 22.23.5; the engine-check workaround in `run-local.ps1` is removed and `engineStrict` applies everywhere |
| IMP-06 | **14-day dependency cooldown**: versions pinned to releases at least 14 days old (`exclude-newer` in uv, `minimumReleaseAge` in pnpm) | Supply-chain protection: most malicious package releases are detected and removed within days | Decided. Move the date forward deliberately when updating |
| IMP-07 | Synchronous SQLAlchemy sessions (FastAPI runs sync routes in its thread pool); async only for streaming and file upload | Simpler transactions and RLS scoping, same driver for API and worker, and no async ORM pitfalls. Throughput is far above a 3-user local deployment (NFR-07) | Decided |
| IMP-08 | Health: API-87 is `GET /api/v1/health`. Added `/health/live` (liveness), `/health/database` and `/health/model-runtime` (details shown only when `EXPOSE_DIAGNOSTICS` is on, never by default in production) | The setup task asks for `/health/database`, and tooling needs a cheap liveness probe | **Proposed** addition to D09 |
| IMP-09 | Two extra error codes: `method_not_allowed` (405) and `database_unavailable` (503) | D09 §2 has no code for these statuses; the envelope must still be used for every error | **Proposed** addition to D09 §2 |
| IMP-10 | `RawItem` is the adapter output name (D03); D09's `RawRow` is exported as an alias. `fetch(cursor)` yields batches of 500 with a resumable cursor `{"position": n}` | D03 and D09 used two names for the same contract | **Proposed** wording fix in D09 §5 |
| IMP-11 | Non-UTF-8 text files are decoded with `charset-normalizer` and the conversion is reported as a warning; undecodable or binary files are rejected | DR-05 names UTF-8; SVC-02 requires encoding detection. Excel often exports Windows-1252 or UTF-16 | Follows SVC-02; warning text is new |
| IMP-12 | Development-only endpoints `/api/v1/dev/sources/{adapters,preview,validate,fetch}` exercise the real file adapter without auth or storage | Lets the team and mentor see data fetching before auth and schema exist. Replaced by API-14/API-15. Disabled unless `ENABLE_DEV_ENDPOINTS=true`; refused in production | Temporary |
| IMP-13 | Worker reclaims a `running` job whose heartbeat is older than 120 s; retries wait 30 s × 2^(attempt−1), at most 10 min; `max_attempts` default 3 (D07) | D03 SVC-21 requires heartbeats and restartable steps but gives no timings | Values to tune in EXP-01/03 |
| IMP-14 | The base shadcn/ui components (button, card, badge, table, alert, skeleton) were written in the shadcn "new-york" style by hand, because the shadcn registry was not reachable from the build environment. `components.json` is configured, so `pnpm dlx shadcn@4.23.0 add <component>` works on the laptop | Same API and class names as the registry versions; can be replaced one by one with `shadcn add --overwrite` | Decided |
| IMP-15 | uv uses managed CPython builds (`python-preference = "managed"`), and the scripts clear `PYTHONPATH` for their session | Everyone gets the same Python build; this laptop has `PYTHONPATH` set, which would leak foreign packages into the venv | Decided |
| IMP-17 | **Source-fetching layer (SVC-02 + SVC-04).** Normalised records use D07 `feedback_records` names (`raw_text`, `occurred_at`, `occurred_at_missing`, `rating_raw`…); metric rows use `metric_observations` names. Rejected rows carry `{row_number, field, code, message}` (D07 `import_row_errors`). Validation rejects only what the SRS says to reject (empty text DR-07, broken rows, invalid metric rows DR-41); unreadable dates, invalid ratings, long text and repeated record IDs are kept and flagged (DR-08). Files over 20,000 records are refused (A-05). Cleaning, PII masking, rating-scale mapping, customer keys, duplicates and spam stay in SVC-05 onwards | Mentor asked for data fetching before the full pipeline; the D03/D06 stage boundaries are kept so the ingest job can reuse these functions unchanged | Implemented |
| IMP-18 | Reader details the design left open: Excel `sep=` hint line; strict CSV quoting (an unclosed quote is an error, not a merged row); header-based delimiter fallback when the sniffer gives up; JSON nested objects flattened to dotted columns (3 levels) so `author.id` can be mapped; transcript speaker turns may start with a time stamp `[00:01:23]`; encoding detected on the first 64 KB (D06 step 2) then decoded strictly | Real exports (Excel, help desks, call tools) need these to be read correctly instead of silently mangled | Implemented |
| IMP-19 | Dates: ISO 8601, epoch seconds/milliseconds, numeric dates and written dates (`python-dateutil`, named in D06 step 7). Day/month order is inferred once per column; when every value is ambiguous (`03/04/2026`) day-month-year is assumed and the validation report says so. Partial dates (`October 2026`) are refused rather than completed with invented parts | Avoids silently wrong timestamps, which would corrupt trends | Implemented. **Proposed**: an explicit date-order choice in the mapping if teams need it |
| IMP-20 | API additions to D09 shapes: `SourceFileOut` gains `record_count`, `required_fields`, `suggested_mapping`; `ColumnMapping.text` is optional for `metrics`; new development endpoints `POST /dev/sources/validate` and `/fetch` (cursor bound to the file's hash); `/dev/sources/map` removed (replaced by `/fetch`) | UI-03 needs suggestions and a validation summary before API-15 exists | **Proposed** additions to D09 |
| IMP-21 | **Product name: Elucis AI** (**E**vidence-**L**ed **U**nified **C**ustomer **I**ntelligence **S**ystem; tagline "Illuminate insights. Engineer better products."). Applies to everything a user sees: app name, page titles, API title, READMEs. The SRS and design documents keep the project title "AI Product Manager Copilot". Internal identifiers were renamed from "copilot" to "elucis" on 25 Nov 2026, before any database was created: Python package `elucis`, distribution `elucis-backend`, CLI scripts `elucis-worker`, `elucis-db-check` and `elucis-ollama-check`, databases `elucis_dev` and `elucis_test`, bootstrap password variables `ELUCIS_*_PASSWORD`, service id `elucis-api`, logger names `elucis.*` and database `application_name` values `elucis-*`. Dependency versions did not change. Not renamed: the project folder, the SRS and design documents, and the Jira marker `ai-pm-copilot:` (a D02/D03 design decision) | Resolves F-05 (the "Copilot" trademark risk). Chosen by the team on 25 Nov 2026 | Decided, with a known risk: "Elucis" is the name of an FDA-cleared surgical-planning product (Realize Medical, 510(k) K220649) and a US trademark record for ELUCIS exists (serial 90837849). Acceptable for the internship and portfolio; get a trademark opinion or rename before any commercial release |
| IMP-22 | **Schema conventions (migration 0002).** Hand-written DDL, never autogenerated; models mirror it with the same explicit object names. Unspecified `ON DELETE` is NO ACTION (checked at statement end, so a workspace cascade still clears everything; an import with records cannot be deleted implicitly). Gaps the design leaves, filled conservatively: nullability for the short-form tables in D07 §3.5–3.11 (identity, FK and status columns NOT NULL; notes and optional timestamps nullable); `UNIQUE (workspace_id, id)` on `llm_call_records` so it can be referenced by composite FKs; references to `llm_call_records` use `ON DELETE SET NULL (llm_call_id)`, so the 90-day purge (D07 §8) never needs to touch results; `workspaces.current_analysis_run_id` is a composite deferrable FK with `SET NULL (current_analysis_run_id)`; `roadmap_items` gains `UNIQUE (workspace_id, roadmap_id, id)` so both ends of a dependency must be in the same roadmap (D08 §7); CHECKs for D07's prose rules: canonical ask ≤ 12 words, AI score inputs need a rationale, opportunity `source_kind` matches its source, theme name 1–60 and description ≤ 200 characters, share 0–1, file size 0–20 MB; text identifiers have no CHECK where D07 gives none (`llm_call_records.call_id`). **Correction:** D07's `CHECK (duplicate_of IS NULL OR exclusion_reason = 'duplicate')` passes when the reason is NULL, so it is written `IS NOT DISTINCT FROM 'duplicate'`. Table list: exactly the 54 D07 tables, no intentional difference | D07 is the source; the drift test compares models and live schema, and every rule above has a test | **Proposed** additions to D07 |
| IMP-23 | **Privileges and RLS.** Every privilege is granted per table after `REVOKE ALL` (independent of default privileges). app_api and app_worker: full DML on tenant tables, users, sessions, workspaces and memberships; `audit_logs` SELECT and INSERT only (SEC-15); `llm_call_records`, `login_attempts` and `prompt_versions` SELECT and INSERT, with DELETE on the first two for the worker's retention purges; `score_inputs` SELECT, INSERT and UPDATE of `is_current` and `superseded_at` only (FR-PRI-04). RLS enabled and forced on the 48 tenant tables with `tenant_isolation`; the policy uses `nullif(current_setting('app.workspace_id', true), '')::uuid`, because after a `SET LOCAL` transaction a pooled connection reads the setting back as `''`, which D07's bare cast would turn into an error instead of "no rows". `jobs` adds `worker_queue_read`/`worker_queue_update` for app_worker (claim, heartbeat, finish across workspaces; no cross-workspace INSERT or DELETE). `audit_logs` has `audit_read` (own workspace), `audit_insert` (own workspace or NULL) and `audit_global_read` (NULL rows, app_owner only). No RLS on `workspaces` and `workspace_memberships`, as in D07 §5 (decided 26 Nov 2026) | D07 §5, D10 §3 | Decided; the `nullif` form and `audit_global_read` are **proposed** wording for D07 §5 |
| IMP-24 | **Workspace deletion and audit (FR-AUTH-11, SEC-14, A-21).** `audit_logs.workspace_id` references `workspaces` with ON DELETE CASCADE, so a workspace's audit history goes with it. The `delete_workspace` job deletes the workspace and, in the same transaction, inserts `workspace.deleted` with `workspace_id` NULL, the actor, the time, `target_type 'workspace'`, the workspace ID as `target_id` and `details = {"workspace_name": …}`, never customer text. Only app_owner can read it afterwards | Decided 26 Nov 2026; tested in `test_workspace_deletion_keeps_only_the_deletion_event`. The job itself is built with SVC-01/SVC-21 | Decided |
| IMP-25 | `app_readonly` (D10 §3) is not created yet: there are no evaluation scripts to use it, and an unused login is only a credential to protect | Decided 26 Nov 2026 | **Proposed**: add it with SVC-22 (bootstrap + grants migration) |
| IMP-26 | Tests connect as the real roles: `TEST_DATABASE_API_URL` and `TEST_DATABASE_WORKER_URL` (app_api and app_worker on `elucis_test`). `20-setup-project.ps1` adds keys missing from an existing `.env` using the passwords already in it, without printing them. Each test session migrates a throwaway schema with Alembic | RLS and grants can only be proven as non-owner roles | Decided |
| IMP-27 | **`APP_ENCRYPTION_KEY` is a real Fernet key** (AGR-16): 32 random bytes, URL-safe base64, 44 characters. `20-setup-project.ps1` generates one (`New-FernetKey`) and replaces an existing value that is not a valid key, rewriting only that line of `.env` without printing it; safe because nothing is encrypted before SVC-20. Settings validate the format at startup with an error that says how to fix it. All settings errors hide the rejected input (`hide_input_in_errors`), because pydantic otherwise echoes the value, and a rejected value is often a secret or a URL with a password | The old scripts wrote a 64-character random string, which Fernet rejects, so the first credential save would have failed at runtime. Found 26 Nov 2026 | Implemented; the laptop's `.env` was repaired |
| IMP-28 | **Sessions, CSRF and sign-in (SVC-01).** Cookie `session` (HttpOnly, SameSite=Lax, Path=/api, Secure from `SESSION_COOKIE_SECURE`, default on in production); 256-bit token stored only as SHA-256; idle 30 min (A-07) and absolute 12 h; `last_seen_at` written at most once a minute; token rotated at sign-in, deleted at sign-out. The CSRF token is HMAC-SHA256(`SESSION_SECRET`, session token): D07 stores only `csrf_token_hash` while D09 has `GET /auth/me` return the token, so it is derived rather than stored and survives a page reload without rotating (which would break other tabs). Throttling: 5 failures in 15 min per account (A-08) and **20 per IP address** (D10 asks for a per-IP limit without a number); blocked attempts are not counted, so the block ends 15 min after the oldest failure; unknown emails are checked against a dummy hash so timing does not reveal accounts. Retention (D07 §8): each user's expired sessions go at sign-in; the global purge of expired sessions and of login attempts older than 30 days is a worker maintenance step about once an hour, because only `app_worker` may delete login attempts (IMP-23). Client IPs are stored only when they are valid addresses; forwarded headers are not trusted. The development source endpoints (IMP-12) now require a signed-in session (FR-AUTH-02). API-09 runs as a `delete_workspace` job whose own row is removed by the cascade, so the UI confirms completion by polling `GET /workspaces/{ws}` until 404. New error code `encryption_unavailable` (503) when `APP_ENCRYPTION_KEY` or `SESSION_SECRET` is missing. Settings errors never echo rejected values (IMP-27) | D09 §1, D10 §2, D07; decided 26 Nov 2026 with the SVC-01 plan | **Proposed** wording for D09 §1 (CSRF derivation, completion signal of API-09) and D10 §2 (per-IP number) |
| IMP-29 | **`cryptography` 50.0.2** (released 30 Sep 2026, within the cooldown) for Fernet with `APP_ENCRYPTION_KEY` (AGR-16). Each workspace gets 32 random bytes as its customer-key HMAC secret (DR-23), stored Fernet-encrypted in `workspaces.customer_key_secret` as D07 §3.1 specifies. Its only dependency, `cffi`, was already locked | Approved by the owner 26 Nov 2026 | Decided |
| IMP-16 | **Product identity and design system.** The product name lives in one constant (`frontend/src/config/product.ts`); internal programme labels never appear in the UI (a test enforces it). Tokens: Lagoon `#0E6F7C` for actions and focus, Marigold reserved for evidence and attention, cool neutrals; light, dark and system themes; IBM Plex Sans (self-hosted through `@fontsource-variable/ibm-plex-sans` 5.3.0, OFL licence, no CDN calls). Navigation follows D12 §2; sections not yet built are shown disabled, never as placeholder pages | A product, not a project demo; D12 defines the shell; local-first means no third-party font CDN | Decided |
