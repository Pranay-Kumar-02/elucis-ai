# 07 · Database Schema and Data Dictionary

PostgreSQL 18.7 with pgvector 0.8.7 [V]. Design only: no migrations are produced here.

## 1. Design principles

| Topic | Decision |
|---|---|
| Normal form | Third normal form. Documented derived tables: `theme_run_stats`, `score_snapshots` (snapshots for speed and history, written only by services) |
| Multi-tenancy | Every tenant table has `workspace_id NOT NULL`. Foreign keys between tenant tables are composite `(workspace_id, x_id)`, so a row cannot reference another workspace's row |
| Row-level security | Enabled and forced on every tenant table (ADR-11); policy `workspace_id = current_setting('app.workspace_id')::uuid`; set per transaction with `SET LOCAL` (§5) |
| Raw versus processed | `raw_text` immutable (trigger blocks updates, DR-35); `processed_text` is the masked, cleaned text used everywhere downstream (DR-29, DR-33) |
| Versioning of AI outputs | Classifications and memberships keyed by `analysis_run_id`; documents versioned; every AI output references `llm_call_records` and `prompt_versions` (DR-34) |
| Human overrides | Stored as data (`theme_overrides`, `score_inputs.origin='person'`, review resolutions), never as edits that a re-run would overwrite (FR-THM-12, FR-PRI-04) |
| Enumerations | `text` with `CHECK` constraints (easier to evolve than PostgreSQL enum types) |
| Identifiers | `uuid` primary keys generated by `gen_random_uuid()`; `bigint identity` for high-volume append-only logs |
| Time | `timestamptz` stored in UTC (DR-21) |
| Vectors | `vector(1024)` assumes the embedding model's dimension is 1,024; confirmed in EXP-04 at setup. A model with a different dimension needs a new column and index, created by a migration plus a `reembed` job |

## 2. Conventions

**STD columns** (on every tenant table unless stated):

| Column | Type | Null | Default | Notes |
|---|---|---|---|---|
| id | uuid | No | `gen_random_uuid()` | Primary key |
| workspace_id | uuid | No | | FK → workspaces(id) ON DELETE CASCADE; part of composite FKs |
| created_at | timestamptz | No | `now()` | |

Every STD table also has `UNIQUE (workspace_id, id)` so other tables can reference `(workspace_id, id)`. FK notation below: `→ table` means a composite FK on `(workspace_id, column)` unless marked "global".

## 5. Row-level security design

```sql
ALTER TABLE feedback_records ENABLE ROW LEVEL SECURITY;
ALTER TABLE feedback_records FORCE ROW LEVEL SECURITY;
CREATE POLICY tenant_isolation ON feedback_records
  USING (workspace_id = current_setting('app.workspace_id', true)::uuid)
  WITH CHECK (workspace_id = current_setting('app.workspace_id', true)::uuid);
```

- Applied to every STD table and to `record_embeddings`, `claim_evidence`, `roadmap_dependencies`, `llm_call_records`, `audit_logs` (audit read policy).
- The API sets `SET LOCAL app.workspace_id = '<uuid>'` at the start of each request transaction, after the membership check. Unset means no rows (`current_setting(..., true)` returns null).
- Roles: `app_owner` owns tables (migrations only); `app_api` and `app_worker` are not owners, so RLS applies. `app_worker` additionally has a policy on `jobs` allowing claims across workspaces, then sets `app.workspace_id` to the job's workspace before processing.
- Global tables (users, sessions, login_attempts, prompt_versions) are not tenant-scoped and are accessed only by SVC-01 and the gateway.

## 8. Retention

| Data | Retention |
|---|---|
| Raw and processed feedback, analysis results, documents | Lifetime of the workspace; deleted with the workspace (FR-AUTH-11) or import removal (FR-ING-12) |
| Audit logs | Lifetime of the workspace (A-21) |

| Login attempts | 30 days |

| Uploaded files | Kept with their import; removed with the import or workspace |
